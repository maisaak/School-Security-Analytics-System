# Проверка и восстановление локальной копии

Поддерживается стандартная SQLite-база `school_security.db`. Для PostgreSQL и нестандартного расположения БД используйте штатные инструменты своей установки. Скрипт теперь отказывается создавать «полную» копию без стандартной БД.

## Создание

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts\backup_data.py
```

На Linux используйте `.venv/bin/python scripts/backup_data.py`. Сохраняются база, media, пользовательский датасет и кандидаты моделей. `.env`, виртуальное окружение и исходный код не копируются. Это не полный образ сервера. Для согласованного снимка файлов остановите API, фоновые задания и обучение.

В завершённой копии есть `manifest.json` с размером и SHA-256 каждого файла, а также `BACKUP_COMPLETE.txt`. Копия с `BACKUP_FAILED.txt` непригодна для восстановления. Ссылки и junction отклоняются, чтобы не скопировать внешние файлы или секреты. Проверки рассчитаны на доверенный локальный каталог, не на одновременную враждебную подмену файлов.

## Проверка без восстановления

```powershell
.\.venv\Scripts\python.exe scripts\restore_data.py "backups\school_security_ИМЯ_КОПИИ"
```

Проверяются манифест, состав файлов, контрольные суммы и целостность SQLite. Старые копии без манифеста этим инструментом не восстанавливаются: сохраните их и проверяйте отдельно. Контрольные суммы обнаруживают повреждение, но не подтверждают подлинность: злоумышленник с доступом к копии может переписать и манифест.

## Восстановление без перезаписи рабочей установки

```powershell
.\.venv\Scripts\python.exe scripts\restore_data.py "backups\school_security_ИМЯ_КОПИИ" --destination "recovery\checked-copy"
```

Назначение должно быть новой папкой вне копии. Инструмент не перезаписывает существующую папку и не запускает сервер. После копирования заново проверяются уже восстановленные файлы. Частичный результат помечается `BACKUP_FAILED.txt` и сохраняется для диагностики.

Дальнейшее переключение установки выполняет администратор в окне обслуживания: сохранить текущие данные, остановить все писатели, подобрать совместимую версию кода, отдельно вернуть защищённый `.env`, проверить права файлов, запустить и проверить камеры/архив/планы. Автоматического разрушительного восстановления поверх production нет.

Резервные копии содержат персональные данные, хеши паролей и секреты TOTP. Ограничьте доступ средствами ОС, храните зашифрованную внешнюю копию и регулярно проводите пробное восстановление. Скрипт не шифрует данные и не удаляет старые копии автоматически.
