# Результат текущего прохода — 30 октября 2026

## Эксплуатация

- Резервное копирование отказывается от ложного успеха при отсутствии стандартной SQLite.
- Манифест SHA-256, проверка состава/размеров/SQLite, безопасное восстановление в новую папку: `docs/BACKUP_RESTORE.md`.
- Исходные symlink/junction отклоняются; тест создания symlink требует прав ОС и пропущен на текущем Windows.
- Telegram и webhook работают независимо; журналы ошибок не включают URL/токены. Cooldown разделён по типу и имени камеры, число отправляющих потоков ограничено четырьмя. Доставка остаётся best-effort, без гарантированной очереди.
- Updater пытается перезапустить прежний API только при сбое до начала изменения кода. Linux/systemd и Docker не проверены здесь: инструменты отсутствуют.
- Dockerfile больше не маскирует ошибку pip install через `|| true`.

## Внешний вид

- Центр тревог: визуально выбранное событие, читаемая структура, ограниченная прокрутка списка, тематические поля.
- Архив: состояния выбора, единые фильтры, размеры кнопок и поля проверки внутри карточки.
- Зоны, расписания и планы: цвета из темы, выделение дней, согласованные скругления и адаптация.
- Ползунки выбора акцента сохраняют собственные цветовые градиенты, несмотря на общие стили workspace.

## Дополнительный frontend-проход

- Архив: лента по дням, проверка повреждённых presets и значений фильтров до запроса, разделённые loading/mutation states, синхронная блокировка повторного сохранения/удаления.
- План: состояния загрузки/ошибки, размещение клавиатурой, текущие срабатывания, предупреждение при уходе через вкладки и beforeunload, блокировка перехода во время операции.
- Правила: предупреждение о черновиках при закрытии/смене раздела, запрет редактирования во время сохранения, явная обработка незавершённого полигона.
- Медиа: native dialog для инцидента; фото и видео имеют fallback и повтор загрузки.
- Крупный просмотр камеры: повтор MJPEG-подключения при ошибке; устаревшие detections отключённого потока не выделяются как текущие.
- Карточки камер также игнорируют устаревшие detections offline/paused; тестовый диалог переносится внутрь fullscreen-host, кнопка разворота видима при клавиатурном фокусе.
- Список планов: отказ API не маскируется пустым состоянием; доступна повторная загрузка.
- Отказ изображения плана: отдельный повтор без перезагрузки списка и потери текущего черновика; отмена черновика того же плана не сбрасывает imageReady.
- Фоновое обновление архива сохраняет выбранные ID, пока они присутствуют на странице; смена фильтров/ошибка загрузки очищают выбор.
- Экспорт архива блокирует повторные клики до получения файла, показывает состояние подготовки; набор фильтров с существующим именем можно заменить даже при лимите 30.
- Центр тревог: timestamp watermark и память идентичностей вместо сравнения только соседних окон. Ограничения latest100 явно описаны в интерфейсе и документации.
- Frontend unit tests: 22 passed, включая feed с повреждённым/задержанным временем, ограничение памяти и валидацию сохранённых настроек видеостены. Это тесты чистых функций/события, не React DOM или скриншотные тесты. Transpile использует современный ES2022 target, чтобы тесты Set/spread соответствовали приложению, а не устаревшему ES5 downlevel.
- Невыполненный ручной browser checklist: `docs/MONITORING_UI_CHECKLIST.md`.
- Последняя frontend-сборка после восстановления изображения плана, уточнения счётчика тревог, валидации локальных настроек видеостены и блокировки повторного экспорта: `npm.cmd run build` — успешно.
