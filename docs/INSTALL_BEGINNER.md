# Установка с нуля: пошаговый гайд для новичков

Этот гайд поможет запустить School Security Analytics System **на своём компьютере**, открыть интерфейс и попробовать систему без настоящих камер.

Не нужно заранее знать Python или программирование. Но потребуется интернет, свободное место для ML-зависимостей и немного времени: первая установка может быть долгой.

> Это локальный пробный запуск, а не развёртывание школьной системы охраны. Не открывайте порты в роутере и не публикуйте приложение в интернет. Качество распознавания на ваших камерах необходимо проверять отдельно.

## Сначала выберите свою систему

- **Windows:** начните с [инструкции для Windows](#часть-1-установка-на-windows).
- **Ubuntu / Debian Linux:** перейдите к [инструкции для Linux](#часть-2-установка-на-linux).
- Уже установили? Нужны [первый вход](#часть-3-первый-вход-и-пробный-запуск), [повторный запуск](#как-запустить-систему-в-следующий-раз) или [помощь при ошибках](#если-что-то-не-получилось).

## Как читать команды в этом гайде

**Терминал** — окно, куда вводят команды. В Windows будем использовать PowerShell, в Linux — обычный терминал.

1. Копируйте команды из блока **по одной строке**.
2. Вставляйте строку в терминал и нажимайте `Enter`.
3. Дождитесь окончания команды, прежде чем вводить следующую.
4. Не копируйте оформление блока и значки приглашения вроде `PS C:\…>` или `$`.

Обычно команда закончилась, когда снова появилась строка, в которую можно вводить текст. **Серверы — исключение:** они продолжают работать, пока окно открыто. Это нормально.

> Если команда спрашивает подтверждение установки, прочитайте вопрос. Для обычного подтверждения может понадобиться `Y` и `Enter`. Окно разрешения Windows показывается отдельно — проверьте, что оно относится к устанавливаемой программе.

## Часть 1. Установка на Windows

### Шаг 1. Откройте PowerShell

1. Откройте меню **«Пуск»**.
2. Напишите **PowerShell**.
3. Откройте **Windows PowerShell** или PowerShell в приложении **«Терминал»**.

Не обязательно запускать всё окно от имени администратора. Установщики могут отдельно запросить разрешение.

### Шаг 2. Установите необходимые программы

Выполните по очереди:

```powershell
winget install --id Git.Git -e
winget install --id Python.Python.3.13 -e
winget install --id OpenJS.NodeJS.22 -e
winget install --id Gyan.FFmpeg -e
```

Что устанавливается:

| Программа | Зачем нужна |
|---|---|
| Git | Скачать исходники проекта |
| Python 3.13 | Запустить обработку камер и нейросеть |
| Node.js 22 | Запустить веб-интерфейс |
| FFmpeg | Обрабатывать и записывать видео |

Если написано, что программа уже установлена и обновлений нет, это не ошибка. Python должен быть именно версии 3.13, а Node.js — версии 22.12 или новее в ветке 22.

Если команда `winget` не найдена, используйте официальные установщики:

- [Git для Windows](https://git-scm.com/downloads/win) — стандартные параметры установки подходят.
- [Python 3.13](https://www.python.org/downloads/) — выберите выпуск 3.13 и установщик для своей Windows. Оставьте включённым Python Launcher; можно также отметить **Add python.exe to PATH**.
- [Node.js](https://nodejs.org/) — выберите ветку **22 LTS**, npm устанавливается вместе с ней.
- [FFmpeg](https://ffmpeg.org/download.html) — установка через winget проще. Если пока не получилось установить системный FFmpeg, проект также предусматривает fallback через Python-пакет `imageio-ffmpeg`.

**Закройте PowerShell и откройте заново**, чтобы он увидел новые программы.

### Шаг 3. Проверьте установку

```powershell
git --version
py -3.13 --version
node --version
npm.cmd --version
```

Ожидаемый результат — номера версий, например `Python 3.13.x` и `v22.x.x`. Конкретные последние цифры могут отличаться. Если какая-то команда не найдена, смотрите [раздел ошибок](#если-что-то-не-получилось).

### Шаг 4. Выберите папку и скачайте проект

Для простоты будем хранить проект в папке `SchoolSecurity` вашего профиля. Создайте её и перейдите внутрь:

```powershell
New-Item -ItemType Directory -Force "$HOME\SchoolSecurity"
cd "$HOME\SchoolSecurity"
git clone https://github.com/maisaak/School-Security-Analytics-System.git
cd School-Security-Analytics-System
```

**Вы сейчас находитесь в корне проекта.** Это папка, внутри которой лежат `README.md`, `backend`, `frontend` и `ml`.

Проверить содержимое можно командой:

```powershell
dir
```

Если папка с проектом уже существует, не скачивайте её поверх существующей. Возможно, вы уже проходили установку — тогда перейдите к [повторному запуску](#как-запустить-систему-в-следующий-раз).

### Шаг 5. Установите Python-зависимости

В том же окне:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
```

Первая команда создаёт отдельное окружение проекта. Оно не требует ручной активации и не должно удаляться после установки.

Последняя команда скачивает много пакетов, в том числе библиотеки нейросети. **Не закрывайте окно**, пока установка не закончится. Размеры загрузок могут быть большими; скорость зависит от интернета.

Если в конце появился `ERROR`, не переходите дальше — сохраните текст ошибки.

### Шаг 6. Создайте настройки и секретный ключ

```powershell
.\.venv\Scripts\python.exe scripts/setup_env.py
```

В корне проекта появится файл **`.env`** с настройками и случайным ключом администратора.

Если вы видите `.env already exists; nothing changed.`, файл уже создан. Это защитное поведение: существующие ключи не перезаписываются.

### Шаг 7. Запустите сервер обработки

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Дождитесь строк наподобие:

```text
Application startup complete.
Uvicorn running on http://127.0.0.1:8000
```

**Оставьте это окно открытым.** Здесь работает backend — сервер обработки. Пока он работает, обычная строка для ввода команд не возвращается.

### Шаг 8. Откройте второй PowerShell и запустите интерфейс

Откройте **ещё одно** окно PowerShell через меню «Пуск». Выполните:

```powershell
cd "$HOME\SchoolSecurity\School-Security-Analytics-System\frontend"
npm.cmd ci
npm.cmd run dev
```

Дождитесь сообщения Vite с адресом `http://localhost:3000`.

**Оба окна должны оставаться открытыми:** первое обрабатывает данные, второе показывает веб-интерфейс. Закрытие браузера не останавливает эти процессы.

Теперь переходите к [первому входу](#часть-3-первый-вход-и-пробный-запуск).

## Часть 2. Установка на Linux

Инструкция рассчитана на Ubuntu/Debian с графическим рабочим столом. Для других дистрибутивов команды установки пакетов отличаются. На удалённом сервере `localhost` в браузере вашего компьютера не указывает на сервер — эта инструкция не настраивает удалённый доступ.

> Важно: проект проверялся локально на Windows. Инструкция Linux соответствует структуре приложения, но не означает, что все дистрибутивы и камеры отдельно протестированы.

### Шаг 1. Откройте терминал

В Ubuntu обычно работает сочетание **`Ctrl+Alt+T`**. Также можно найти приложение «Терминал» в меню программ.

### Шаг 2. Установите базовые инструменты

```bash
sudo apt update
sudo apt install -y git ffmpeg libglib2.0-0 curl
```

`sudo` может попросить пароль вашей учётной записи Linux. **При наборе пароль не отображается, даже звёздочками.** Введите его и нажмите `Enter`.

### Шаг 3. Установите Python 3.13

Проверьте, установлен ли он:

```bash
python3.13 --version
```

Если команда не найдена, попробуйте:

```bash
sudo apt install -y python3.13 python3.13-venv
```

Если `apt` сообщает, что пакет не найден, в репозиториях вашей версии Linux нет нужного Python. **Не добавляйте случайные репозитории и не заменяйте системный Python.** Используйте подходящий вашей ОС способ установки Python 3.13 либо [Docker-вариант из README](../README.md#запуск-через-docker). До установки Python 3.13 следующие шаги не выполняйте.

### Шаг 4. Установите Node.js 22

Один из вариантов — менеджер версий **nvm**:

1. Откройте [официальный README nvm](https://github.com/nvm-sh/nvm#installing-and-updating).
2. Прочитайте инструкцию и используйте опубликованную там команду установки. Она загружает и запускает скрипт — берите её только из официального репозитория.
3. Закройте терминал и откройте новый.
4. Выполните:

```bash
nvm install 22
nvm use 22
node --version
npm --version
```

Нужна Node.js 22.12+ из ветки 22. Если Node.js уже установлен подходящим способом, повторная установка через nvm не требуется.

### Шаг 5. Скачайте проект

```bash
mkdir -p "$HOME/SchoolSecurity"
cd "$HOME/SchoolSecurity"
git clone https://github.com/maisaak/School-Security-Analytics-System.git
cd School-Security-Analytics-System
```

Проверить, что вы в нужной папке:

```bash
ls
```

В списке должны быть `backend`, `frontend`, `ml` и `README.md`.

### Шаг 6. Установите зависимости и создайте настройки

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/python scripts/setup_env.py
```

Дождитесь окончания каждой команды. Не используйте `sudo pip`: библиотеки устанавливаются в отдельное окружение `.venv`.

### Шаг 7. Запустите сервер обработки

```bash
.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Дождитесь `Application startup complete` и оставьте окно открытым.

### Шаг 8. Запустите интерфейс во втором терминале

Откройте второй терминал и выполните:

```bash
cd "$HOME/SchoolSecurity/School-Security-Analytics-System/frontend"
npm ci
npm run dev
```

Оставьте оба терминала открытыми. Интерфейс: **http://localhost:3000**.

## Часть 3. Первый вход и пробный запуск

### Откройте приложение

1. Запустите обычный браузер: Edge, Chrome или Firefox.
2. В **адресную строку**, а не поиск, вставьте:

   ```text
   http://localhost:3000
   ```

3. Нажмите `Enter`.

`localhost` означает «этот компьютер». Телефон или другой компьютер по такому адресу не увидит вашу установку.

### Найдите ключ администратора

В Windows откройте **третье** окно PowerShell и выполните:

```powershell
notepad "$HOME\SchoolSecurity\School-Security-Analytics-System\.env"
```

В Linux откройте папку проекта в файловом менеджере, включите отображение скрытых файлов (`Ctrl+H`) и откройте `.env` текстовым редактором.

Найдите строку:

```dotenv
API_KEY=здесь_будет_ваш_случайный_ключ
```

Скопируйте **только значение справа от `=`**, без слова `API_KEY=` и без лишних пробелов. Пример выше — не настоящий ключ, вводить его не нужно.

На странице входа:

1. Отметьте **«Войти ключом администратора»**.
2. Вставьте свой ключ.
3. Нажмите **«Войти»**.

Готовой пары `admin/admin` нет. Ключ нельзя публиковать, пересылать посторонним или показывать на скриншотах. Файл `.env` не нужно переименовывать в `.env.txt`.

### Создайте обычную учётную запись

1. Откройте вкладку **«Настройки»**.
2. Найдите **«Доступ сотрудников»**.
3. Укажите логин, имя и пароль длиной не менее 12 символов.
4. Выберите роль:
   - **Наблюдатель** — только просмотр и свои настройки.
   - **Оператор** — ещё анализ файлов и подтверждение инцидентов.
   - **Администратор** — управление системой и сотрудниками.
5. Нажмите **«Создать сотрудника»**.

Логин задаётся строчными латинскими буквами, цифрами и разрешёнными разделителями, длина 3–64 символа. Не выдавайте всем административные права.

После выхода можно входить логином и паролем, **сняв галочку входа ключом**.

### Попробуйте систему без настоящей камеры

1. Войдите администратором.
2. Откройте **«Мониторинг и инциденты»**.
3. Нажмите добавление камеры.
4. Задайте понятное имя, например «Пробная камера».
5. В поле адреса потока укажите:

   ```text
   sim://entrance
   ```

6. Сохраните камеру и дождитесь появления изображения.

Это демонстрационная сцена, а не настоящая трансляция. Можно проверить кнопки симуляции в карточке, появление событий и архив. Проверка на искусственной сцене не подтверждает качество охранного распознавания.

### Попробуйте YOLO11

1. Откройте **«Настройки» → «Версия YOLO»**.
2. Для начала выберите **YOLO11 · N** — лёгкий вариант.
3. Если весов нет, включите разрешение загрузки официальных весов.
4. Нажмите **«Применить модель»** и дождитесь результата.

Загрузка требует интернета и может занять время. Не нажимайте кнопку многократно. Стандартная YOLO11 распознаёт COCO-объекты; специализированная модель оружия работает отдельно.

### Настройте внешний вид

В разделе **«Мой интерфейс»** выберите число колонок, видимость статистики и журнала, компактный режим и стартовую страницу. Нажмите **«Сохранить интерфейс»**.

Эти настройки принадлежат текущей учётной записи, а не всем сотрудникам. Скрытие журнала или баннера не останавливает запись событий.

## Как подключить настоящую камеру

Переходите к этому шагу после знакомства с демонстрацией.

1. Узнайте у администратора сети **статический IP камеры**, RTSP-адрес, логин и пароль. Адрес интерфейса камеры в браузере — не обязательно адрес RTSP-потока.
2. Проверьте воспроизведение RTSP-адреса в VLC на том же компьютере.
3. Откройте `.env` и найдите `CAMERA_ALLOWED_HOSTS=[]`.
4. Укажите разрешённый IP, например:

   ```dotenv
   CAMERA_ALLOWED_HOSTS=["192.168.1.20"]
   ```

5. Сохраните файл и перезапустите **сервер обработки**: нажмите `Ctrl+C` в его терминале, затем повторите команду запуска backend для вашей ОС.
6. Добавьте камеру в интерфейсе с её настоящим адресом. Пример структуры:

   ```text
   rtsp://USER:PASSWORD@192.168.1.20:554/stream
   ```

`USER`, `PASSWORD`, IP и `/stream` здесь — placeholders: замените их реальными данными. Не пересылайте адрес с паролем в открытые чаты. Если вы не знаете сетевые настройки, обратитесь к администратору — не отключайте защиту ради подключения.

## Как остановить систему

В каждом из двух терминалов сервера нажмите **`Ctrl+C`**. Если Windows спрашивает, завершить ли пакетный файл, подтвердите завершение.

После остановки окна можно закрыть. Камеры, сотрудники и настройки сохраняются в БД. **Во время остановки компьютера или серверов мониторинг не ведётся.**

## Как запустить систему в следующий раз

**Переустанавливать программы, скачивать проект и запускать `setup_env.py` каждый раз не нужно.** Не удаляйте `.env`, `.venv` и базу данных.

### Windows: два окна PowerShell

Первое окно:

```powershell
cd "$HOME\SchoolSecurity\School-Security-Analytics-System"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Второе окно:

```powershell
cd "$HOME\SchoolSecurity\School-Security-Analytics-System\frontend"
npm.cmd run dev
```

### Linux: два терминала

Первое окно:

```bash
cd "$HOME/SchoolSecurity/School-Security-Analytics-System"
.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Второе окно:

```bash
cd "$HOME/SchoolSecurity/School-Security-Analytics-System/frontend"
npm run dev
```

Затем откройте **http://localhost:3000**. Если вы выбрали другую папку при установке, подставьте свой путь вместо указанного.

## Если что-то не получилось

| Что видите | Что проверить |
|---|---|
| `git`, `py`, `node` или `npm` не найдены | Установлена ли программа? Откройте новый терминал после установки. В Windows используйте `py -3.13` и `npm.cmd` |
| `No suitable Python runtime found` | Установите Python 3.13 с Python Launcher; проверьте `py -3.13 --version` |
| PowerShell запрещает выполнение скриптов | Используйте прямой путь к Python и `npm.cmd`, как в инструкции; менять ExecutionPolicy не требуется |
| Не найден `backend/requirements.txt` или `scripts/setup_env.py` | Вы не в корне проекта. Вернитесь командой `cd` в папку с `README.md` |
| Не найден `package.json` | Перед npm-командами перейдите в папку `frontend` |
| `npm ci` сообщает о неподходящей версии Node | Проверьте `node --version`; используйте Node.js 22.12+ из ветки 22 |
| `.env already exists; nothing changed.` | Это нормально: настройки уже существуют и сохранены |
| `Задайте API_KEY…` | Убедитесь, что создан `.env`, не `.env.txt`, а `API_KEY` не пустой; затем перезапустите backend |
| Браузер пишет «Не удаётся получить доступ к сайту» | Проверьте оба терминала и адрес `http://localhost:3000`; возможно, серверы остановлены |
| Порт 8000 занят / `address already in use` | Возможно, backend уже работает в другом окне. Не запускайте второй экземпляр; остановите свой старый процесс через `Ctrl+C` |
| Vite выбрал 3001 вместо 3000 | Порт 3000 занят. Освободите его, остановив свой прежний frontend, и запустите снова на 3000; другой порт может не соответствовать CORS-настройкам |
| Страница открылась, но вход не работает | Проверьте http://localhost:8000/health, ошибки backend, правильность ключа и выбранный способ входа |
| Слишком много попыток входа | Подождите не менее минуты и проверьте данные, прежде чем повторять |
| После запуска нет камер и событий | На чистой установке это ожидаемо. Добавьте демонстрационную или настоящую камеру |
| Камера запрещена | Проверьте IP в `CAMERA_ALLOWED_HOSTS` и перезапуск backend после изменения `.env` |
| Всё работает медленно | Используйте N-модель, одну камеру и меньшую нагрузку. CPU может не справляться с выбранным количеством потоков |

**Перед отправкой уберите ключи, пароли камер, cookie и другие секреты.** Не прикладывайте целиком `.env`, базу сотрудников или частные видеозаписи.

## Что сохранить и чего не делать

- Не удаляйте `school_security.db`: при локальном запуске в ней сотрудники, настройки и история.
- Не публикуйте `.env` и не передавайте всем ключ администратора.
- Архив находится в `media/`; датасеты и обученные веса — в `ml/`. Для резервной копии остановите приложение и сохраните БД, `.env` и нужные файлы в защищённом месте.
- Не нажимайте удаление камеры ради «перезапуска»: **камера удаляется вместе с её архивом**.
- Не запускайте обучение на случайных неразмеченных данных и не применяйте кандидата без проверки.
- Не отключайте антивирус, firewall и сетевые ограничения для устранения ошибки установки.
- Не считайте успешный запуск доказательством надёжного обнаружения угроз.
