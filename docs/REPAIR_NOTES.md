# Изменения и границы проверки

Работа выполнена на локальной копии исходного GitHub-репозитория. Публикации, push и развёртывания в школе не выполнялись.

## Исправлено

- Восстановлено одинаковое расположение `backend/app` и `ml` в контейнере и локально.
- `.env` передаётся сервисам явно; генератор создаёт отдельные случайные секреты.
- PostgreSQL/Redis не публикуют хостовые порты, API/UI привязаны к loopback.
- API не запускается без достаточно длинного ключа вне явно включённого DEV_MODE.
- Браузерный вход, HttpOnly cookie, CSRF-header, ограничение попыток, защищённые фото/видео/MJPEG.
- URL камер маскируются в ответах; реальные источники требуют IP allowlist. HTTP выключен по умолчанию.
- Удалено создание успешного обучения с константами метрик. Старая сидированная запись помечается `legacy_unverified` без удаления истории.
- Старые синтетические веса не активны по умолчанию, демо-камеры не создаются автоматически.
- События подтверждаются во времени; для неподвижных сумок добавлен таймер, сброс при потере наблюдения/человеке рядом.
- Захват последнего кадра отделён от инференса, введены сетевые таймауты и восстановление после исключений.
- Запись инцидентов ограничена одним writer на камеру; FFmpeg имеет таймаут, не выдаёт неподдерживаемый fallback за H.264.
- Анализ медиа выполняется в threadpool, не блокируя event loop; видео не ограничивается первыми 90 кадрами, кадры пишутся на диск, а не копятся целиком в RAM.
- Лабораторные события не приписываются первой камере; фото не превращается в поддельное видео; общие медиа не удаляются пока на них есть записи.
- Идемпотентное подтверждение, валидация пагинации, UTC-время API, отображение ошибок/потери связи.
- Обучение без выдуманной авторазметки: подтверждённые bbox, train/val, валидация датасета, кандидат вместо автоматической подмены рабочей модели, ручная активация.
- Ротация архива и просроченных результатов лаборатории; изолированные тестовые БД.
- Обновлён Vite, сборка использует npm lockfile, документация приведена к реальным ограничениям.
- Добавлены YOLOv8/YOLO11 N/S/M/L/X: каталог, подтверждаемая ограниченная загрузка официальных весов, проверка и прогрев до переключения, сохранение выбора, обучение от выбранной базы.
- Учётные записи сотрудников, роли admin/operator/viewer с серверной проверкой, scrypt-пароли и БД-сессии с отзывом при выходе/изменении доступа.
- Персональные настройки интерфейса в БД: колонки, видимость блоков, компактность и стартовая вкладка.

## Что не доказано этими изменениями

- Качество распознавания на реальных школьных камерах и пригодность обучения на пользовательских данных.
- Пропускная способность на GPU/CPU пользователя, круглосуточная стабильность и работа RTSP конкретного производителя.
- Готовность к обработке персональных данных, юридическая совместимость лицензий/весов.
- Отказоустойчивый кластер, неизменяемый аудит и автоматическое восстановление прерванного обучения.

В текущей среде нет Docker и реальных RTSP-камер. Проверены локальные тесты и сборка UI; Compose требует отдельного прогона на машине с Docker. Настоящее обучение на реальном датасете не проводилось: исходные 48 синтетических изображений не заменены на выдуманный «реальный» набор.

### Результаты локального прогона

- `python -m pytest -q`: **53 passed**, одно предупреждение совместимости Starlette/httpx (не ошибка тестов). Проверены роли, отзыв сессий, изоляция настроек, каталог моделей, загрузка весов, аудит, статусы проверки инцидентов и cooldown уведомлений.
- Добавлены локальные install/start/stop-скрипты Windows/Linux, `/display` для поста наблюдения со звуковым сигналом, администраторская диагностика, резервное копирование SQLite и необязательные Telegram/webhook-уведомления.
- `npm run build`: TypeScript и production-сборка Vite успешны.
- YOLO11n: официальные веса загружены; выполнены прогрев и настоящий инференс на изображении собаки (обнаружен класс dog). Остальные размеры YOLO11 отдельно не прогонялись; это не оценка качества на школьных камерах.
- Обновлённый backend: успешный HTTP-прогон через Vite proxy — вход администратора, сессия с ролью, чтение/сохранение собственных настроек, каталог 10 моделей, список сотрудников и отзыв сессии при выходе.
- `npm audit`: 0 известных уязвимостей на момент проверки.
- `python scripts/smoke_live.py`: успешный HTTP-прогон через Vite proxy с реальным backend и YOLO: вход, временная sim-камера, событие собаки именно этой камеры, защищённое фото, MP4 и MJPEG, удаление временной камеры/архива и выход.
- Страница входа открыта в браузере. Полный браузерный пользовательский сценарий и ручная разметка мышью отдельно не автоматизированы.

`scripts/smoke_live.py` запускается только вручную при работающих API и фронтенде. Он создаёт свою временную демо-камеру и удаляет её вместе с собственным архивом. Не запускайте его на загруженной боевой установке.

## Перед пилотом

1. Развернуть в изолированной сети, настроить HTTPS, ключи, allowlist камер и исходящий firewall.
2. Проверить Compose, PostgreSQL, Redis/Celery, перезапуск всех сервисов, потерю камеры/сети и заполнение диска.
3. Подготовить независимые train/val/test с разрешённым использованием, полной разметкой и отрицательными примерами.
4. Измерить recall/precision по классам, false alerts на камеро-час, задержку от события до оператора, пропуски маленьких/закрытых объектов.
5. Определить политику хранения и резервного копирования, разграничение доступа и журнал действий.
6. Провести длительные нагрузочные испытания и настроить правила/пороги под каждую сцену. Решение об эксплуатации принимает ответственная организация, а не показатель mAP в UI.
