# 🏫 School Security Analytics System

Система видеомониторинга: RTSP-камеры → YOLO → кандидаты инцидентов → фото/видеоклипы → проверка оператором.

**Статус: прототип для контролируемых испытаний, не сертифицированная система охраны.** Наличие нейросети не гарантирует обнаружение оружия. До внедрения нужны независимые реальные записи, оценка пропусков/ложных тревог, проверка защиты персональных данных и испытания 24/7. Не заменяет охрану и другие меры безопасности.

## Возможности

- Добавление, пауза и удаление RTSP-камер без перезапуска сервера.
- MJPEG-видеостена, фактические FPS, задержка инференса, статус потока и переподключение.
- Отдельный захват последнего кадра: медленный инференс не должен накапливать очередь старого видео.
- Выбор базового COCO-детектора: YOLOv8 и YOLO11, размеры N/S/M/L/X; отдельный детектор оружия и опциональная кастомная модель.
- Временное подтверждение событий. Для сумки — непрерывное наблюдение приблизительно неподвижного объекта без человека рядом (30 секунд по умолчанию).
- Архив, фильтры, фото, H.264 MP4, подтверждение проверки, пагинация API.
- Лаборатория: фото/видео до 120 секунд, с явным отказом для слишком длинного файла вместо скрытого обрезания. События загрузок относятся к лаборатории, а не к реальной камере.
- Ручная разметка одного объекта в браузере; отдельные train/val. Для сложных снимков — внешняя полная YOLO-разметка.
- Обучение кандидата через Celery или локальный процесс, реальные метрики валидации, **ручная активация** и возврат к ранее обученному кандидату.
- Учётные записи сотрудников с ролями, вход по логину/паролю или ключу администратора, отзыв сессий, HttpOnly/SameSite-cookie и CSRF-проверка изменений.
- Персональные настройки видеостены, видимости блоков, компактного режима и стартовой страницы.

## Быстрый старт: Docker

Требуются Docker Engine/Desktop с Compose v2 и Python для генерации конфигурации.

```bash
python scripts/setup_env.py
docker compose up -d --build
```

Скрипт создаёт `.env` со случайными `API_KEY` и `POSTGRES_PASSWORD`, **не перезаписывая существующий файл**. Для первого входа включите «Войти ключом администратора» и используйте `API_KEY` из `.env`. Не публикуйте файл и не вставляйте секрет в URL.

- Интерфейс: http://localhost:3000
- API: http://localhost:8000
- Swagger: http://localhost:8000/docs (для запросов нажмите Authorize и введите API_KEY).
- Проверка процесса: http://localhost:8000/health. Это не проверка исправности всех камер или качества детекции.

По умолчанию **нет камер, событий и выдуманных метрик обучения**. БД и Redis не публикуют порты на хост. Фронтенд и API доступны только на loopback. Для доступа по сети настройте HTTPS reverse proxy, `COOKIE_SECURE=true`, конкретные `CORS_ORIGINS`, firewall и отдельную сеть камер. Не публикуйте dev-сервер Vite в интернет.

### Подключить камеру

1. Задайте статический IP в `.env`, например `CAMERA_ALLOWED_HOSTS=["192.168.1.20"]`.
2. После изменения настроек перезапустите backend: `docker compose up -d --force-recreate backend celery_worker`.
3. В интерфейсе добавьте `rtsp://USER:PASSWORD@192.168.1.20:554/stream` с реальным адресом потока вашей камеры.

В рабочем режиме разрешены только явно перечисленные статические IP. Loopback, link-local и служебные имена запрещены. HTTP-источники отключены по умолчанию; включать `ALLOW_HTTP_CAMERAS=true` можно только для доверенной камеры с ограниченным сетевым доступом. Проверка URL не заменяет сетевой firewall (редиректы/протоколы FFmpeg требуют ограничения исходящих соединений).

### Демонстрация без камер

Добавьте вручную `sim://entrance`, `sim://hallway`, `sim://courtyard`. Либо включите `SEED_DEMO_CAMERAS=true` перед первым запуском пустой БД.

`ml/models/school_security_best.pt` — унаследованные демонстрационные веса, **по умолчанию не активны**. Чтобы отдельно исследовать старое демо, можно указать этот путь в `YOLO_CUSTOM_MODEL_PATH`, но это не делает модель пригодной для реальной охраны. Синтетический генератор сохранён как учебный пример; API не генерирует его данные автоматически и не допускает `seed_*` в рабочее обучение.

## Локальная разработка

Проверено на Windows с Python 3.13 и Node.js 22+. Docker-образ backend использует Python 3.13. Требуется FFmpeg; при отсутствии системного бинарника используется `imageio-ffmpeg`.

```bash
python scripts/setup_env.py
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS вместо предыдущей строки: source .venv/bin/activate
pip install -r backend/requirements.txt
python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

В другом терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:3000, войдите ключом из `.env`. При локальном `ENABLE_LOCAL_TRAINING=true` Redis не обязателен для обучения. В Docker эта настройка принудительно выключена: нужен Celery worker.

**Не используйте несколько uvicorn workers или несколько backend-реплик:** менеджер камер, сессии с ограничением попыток входа и блокировки задач рассчитаны на один экземпляр API. Для горизонтального масштабирования нужно отдельное управление потоками и распределённые блокировки.

## Настройки, модели и сотрудники

После входа откройте вкладку **«Настройки»**.

- **Мой интерфейс** доступен каждому: 1–4 колонки видеостены (с адаптацией под узкий экран), статистика, журнал, баннер тревог, компактный режим и стартовая вкладка. Сохранение отдельно для каждой учётной записи; скрытие блока не меняет права доступа.
- **Версия YOLO** изменяется администратором для всех камер. Выберите YOLOv8 или YOLO11 и размер N/S/M/L/X, разрешите загрузку отсутствующих официальных весов и нажмите «Применить модель». Нужен доступ к GitHub; большие модели требуют больше памяти и времени. Перед заменой выполняется проверка и прогрев; при ошибке загрузки/проверки прежний детектор остаётся активным. Выбор сохраняется в БД.
- Переключается базовый COCO-детектор, а не специализированные веса оружия или активный кастомный кандидат. Стандартная YOLO11 сама по себе не является детектором оружия. Новые задачи обучения используют выбранную базу.
- **Доступ сотрудников**: администратор задаёт уникальный логин латиницей (3–64 символа), имя, пароль от 12 символов и роль. Пароли хранятся как scrypt-хеши. Передавайте пароль безопасным способом, не общий API_KEY.

| Роль | Возможности |
|---|---|
| Наблюдатель | Камеры, архив, аналитика, свои настройки интерфейса |
| Оператор | То же + проверка фото/видео и подтверждение инцидентов |
| Администратор | То же + камеры, удаление записей, модели, обучение, сотрудники |

Отключение сотрудника, изменение роли или пароля отзывает его сессии. Выход также отзывает сессию на сервере. Самостоятельно отключить или понизить свой административный доступ нельзя. После обновления со старой версии потребуется войти заново; ротация API_KEY аннулирует все выданные сессии.

## Обучение без подмены результатов

1. Соберите реальные примеры с правами на использование. Разделите train/val **по камерам/времени съёмки**, а не соседним кадрам одного ролика. Для окончательной оценки держите дополнительный независимый test-набор.
2. Разметьте **все** объекты целевых классов. Встроенный редактор рассчитан на один объект. Не загружайте многопредметную сцену как один bbox.
3. Структура:

```text
ml/datasets/custom/
  images/train/*.jpg
  images/val/*.jpg
  labels/train/*.txt
  labels/val/*.txt
```

YOLO-строка: `class_id center_x center_y width height`, координаты нормированы в 0–1. Классы: `0 dog`, `1 weapon`, `2 suspicious_bag`. Последний класс обозначает **сумку-кандидат**, не намерения владельца и не содержимое.

4. Откройте «Обучение» и запустите задачу. Проверяется наличие файлов, рамки, классы, отсутствие точных дубликатов train/val и синтетических `seed_*`. Минимум 6 train / 3 val — **технический порог, не достаточный объём для качества**. Проверки не выявляют все виды утечки и ошибок разметки.
5. Результат сохраняется в `ml/models/candidates/job_ID.pt`, статус `ready`. Рабочие камеры продолжают использовать старую модель. Каждый запуск — transfer learning от базового COCO; это не продолжение предыдущего обучения.
6. Проверьте кандидата отдельно, например через Ultralytics `yolo predict model=... source=...`, и измерьте качество на независимом test-наборе. API возвращает метрики val, но не удостоверяет пригодность к эксплуатации.
7. Только затем нажмите «Применить после проверки». Для возврата примените прежний кандидат из журнала; его файл должен оставаться на диске. Не загружайте чужие непроверенные `.pt`: это сериализованные модели, требующие доверия к источнику.

Если сервер/воркер аварийно завершился во время обучения, задача может остаться `queued/running`. Не запускайте второй процесс поверх неё: убедитесь в отсутствии живого процесса обучения и восстановите статус в БД. Автоматическое восстановление распределённых задач пока не реализовано.

## API

Скрипты передают `X-API-Key`. Браузер использует cookie, полученную через `POST /api/auth/login`; изменяющие запросы также требуют `X-Requested-With: SchoolSecurity`. Ключи в query string не принимаются. Фото, видео и MJPEG требуют той же авторизации.

| Метод | Путь | Назначение |
|---|---|---|
| POST / GET | `/api/cameras` | Добавить / получить камеры |
| POST | `/api/cameras/{id}/toggle` | Пауза / продолжение |
| DELETE | `/api/cameras/{id}` | Удалить камеру **и её архив** |
| GET | `/api/cameras/{id}/stream` | MJPEG |
| GET | `/api/violations?limit=100&offset=0` | Архив с фильтрами |
| PATCH | `/api/violations/{id}/ack` | Идемпотентно отметить проверенным |
| GET | `/api/violations/{id}/video` | Видео, если оно существует |
| POST | `/api/analyze/upload` | Проверить файл; сохранение в архив опционально |
| POST | `/api/models/dataset/upload` | Файл, класс, подтверждённый bbox `[x1,y1,x2,y2]`, split |
| POST | `/api/models/retrain` | Обучить кандидата |
| GET | `/api/models/jobs` | Задачи и реальные метрики |
| POST | `/api/models/jobs/{id}/activate` | Явно применить кандидат |
| GET / POST | `/api/employees` | Список / создание сотрудников (администратор) |
| PATCH | `/api/employees/{id}` | Роль, активность, пароль сотрудника |
| GET / PUT | `/api/preferences` | Собственные настройки интерфейса |
| GET | `/api/models/catalog` | Доступные и активные базовые модели |
| POST | `/api/models/select` | Выбор базовой модели (администратор) |

Сохранение в архиве ограничено `MAX_STORED_VIOLATIONS` (по умолчанию 250). Непривязанные результаты лаборатории удаляются через `UPLOAD_RETENTION_HOURS` (24 ч). Очистка выполняется раз в минуту. Настройте требования к хранению и резервные копии **до** реальных испытаний.

## Проверки

```bash
python -m pytest -q
cd frontend
npm ci
npm run build
npm audit
```

Тесты создают временные БД/медиа и не используют рабочий архив. Большинство API-тестов подменяют ответ детектора для воспроизводимости; отдельный smoke-тест вызывает настоящую YOLO на примере собаки. Это проверка интеграции, **не benchmark точности**.

## Известные ограничения

- Нет доказанной точности на школьных камерах, калибровки confidence и отчёта о ложных тревогах/пропусках.
- Собака — обнаруженный объект; безнадзорность не определяется. Содержимое сумок и произвольные «подозрительные предметы» не распознаются.
- Сумки: простое сопоставление рамок/расстояний, а не идентификация владельца или полноценный многокамерный трекинг. Перспектива, перекрытия и прохожие могут влиять на решение.
- Подтверждение оружия требует нескольких наблюдений; краткий показ может быть пропущен.
- Клипы камер содержат предысторию до срабатывания, без гарантированного постсобытийного фрагмента. При низком FPS длительность воспроизведения может отличаться от реального времени.
- Общий lock моделей ограничивает производительность. `MAX_CAMERAS=16` — ограничение ресурсов, **не обещание работы 16 камер на любом CPU**. Измеряйте FPS на своём оборудовании.
- Нет неизменяемого аудита, MFA, самостоятельного восстановления пароля и UI списка всех сессий. API_KEY остаётся аварийным административным доступом: не выдавайте его сотрудникам вместо индивидуальных учётных записей.
- Docker Compose не является полноценной защищённой инфраструктурой; требуется отдельная проверка на целевом сервере.
- Лицензия собственного кода заявлена исходным автором как MIT; отдельного LICENSE в исходном репозитории нет. У Ultralytics и весов отдельные условия, проверьте их до распространения/коммерческого применения.
