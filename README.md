## О проекте

**School Security Analytics System** — веб-приложение для видеомониторинга, анализа изображений и проверки событий оператором. Оно объединяет RTSP-камеры, нейросетевые детекторы и архив в одном рабочем пространстве.

Система помогает заметить объекты и ситуации, требующие внимания: обнаруженную собаку, объект, распознанный специализированной моделью как оружие, или длительно неподвижную сумку без человека рядом. Решение о характере события принимает сотрудник, а не нейросеть.

```text
RTSP-камеры → Захват кадров → Детекторы YOLO → Проверка события во времени
                                                        ↓
Веб-интерфейс ← Камеры, статистика, архив ← Фото и видеоклип
                      ↓
             Проверка сотрудником
```

> [!IMPORTANT]
> Проект — **прототип для контролируемых испытаний**, а не сертифицированная система охраны. Он не заменяет охрану и другие меры безопасности. Качество на реальных школьных камерах пока не подтверждено независимыми испытаниями.

### Технологии

- **Backend:** Python, FastAPI, SQLAlchemy, OpenCV, Ultralytics / PyTorch.
- **Frontend:** React, TypeScript, Vite, Tailwind CSS.
- **Локальный запуск:** SQLite, обучение в отдельном локальном процессе.
- **Docker Compose:** Nginx, API, PostgreSQL, Redis и Celery worker.
- **Авторизация:** scrypt-хеши паролей, серверные сессии, HttpOnly/SameSite-cookie и CSRF-проверка изменений.

### Требования

- **Python 3.13** — версия, на которой проверены зависимости проекта.
- **Node.js 22.12+ из ветки 22 LTS** и npm — для запуска интерфейса без Docker.

- **FFmpeg** — рекомендуется установить системно; при его отсутствии предусмотрен fallback через `imageio-ffmpeg`.

## Установка на Windows

Команды ниже выполняются в **PowerShell**. Проверенный вариант — Python 3.13 и Node.js 22 LTS.

### 1. Установите инструменты

Если используется Windows Package Manager:

```powershell
winget install --id Git.Git -e
winget install --id Python.Python.3.13 -e
winget install --id OpenJS.NodeJS.22 -e
winget install --id Gyan.FFmpeg -e
```

Либо установите их с официальных сайтов: [Git](https://git-scm.com/downloads), [Python](https://www.python.org/downloads/), [Node.js](https://nodejs.org/), [FFmpeg](https://ffmpeg.org/download.html). При установке Python включите добавление в PATH, если планируете использовать команду `python`.

**После установки откройте новое окно PowerShell** и проверьте:

```powershell
git --version
py -3.13 --version
node --version
npm.cmd --version
```

### 2. Скачайте проект и установите backend

```powershell
git clone https://github.com/maisaak/School-Security-Analytics-System.git
cd School-Security-Analytics-System

py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe scripts/setup_env.py
```

Скрипт создаст `.env` со случайными секретами. Существующий `.env` он **не перезаписывает**.

### 3. Запустите backend

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Оставьте терминал открытым. Здесь не требуется активация виртуального окружения, поэтому менять ExecutionPolicy PowerShell не нужно.

### 4. Запустите интерфейс

Откройте **второй терминал** в папке проекта:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте **http://localhost:3000** и перейдите к [первому входу](#первый-вход).

## Запуск через Docker

Потребуются **Docker Compose v2**, Git и Python для генерации `.env`. На Windows используйте Docker Desktop с Linux-контейнерами; на Linux — Docker Engine и Compose plugin. Устанавливать Python-зависимости и Node.js на хост для этого способа не нужно.

### 1. Скачайте проект

```bash
git clone https://github.com/maisaak/School-Security-Analytics-System.git
cd School-Security-Analytics-System
```

### 2. Создайте конфигурацию

Windows PowerShell:

```powershell
py -3.13 scripts/setup_env.py
```

Linux:

```bash
python3 scripts/setup_env.py
```

### 3. Соберите и запустите сервисы

```bash
docker compose up -d --build
docker compose ps
```

Первый запуск может занять время: загружаются образы и ML-зависимости. После запуска интерфейс доступен на **http://localhost:3000**.

Полезные команды:

```bash
# Логи API и фонового обучения
docker compose logs -f backend celery_worker

# Остановка без удаления томов БД
docker compose down

# Пересборка после обновления исходников
docker compose up -d --build
```

PostgreSQL и Redis хранят данные в Docker volumes, а `media/` и `ml/` подключаются из папки проекта. **Не используйте `docker compose down -v`, если хотите сохранить данные БД.** В Compose обучение выполняет Celery worker; `ENABLE_LOCAL_TRAINING` принудительно выключен.

### Скрипты автоматизации локального запуска

После установки без Docker можно использовать скрипты из `scripts/`:

```powershell
# Windows PowerShell
.\scripts\install_windows.ps1
.\scripts\start_windows.ps1
.\scripts\stop_windows.ps1
```

```bash
# Linux
chmod +x scripts/*.sh
./scripts/install_linux.sh
./scripts/start_linux.sh
./scripts/stop_linux.sh
```

Скрипты проверяют базовые инструменты, создают `.venv`, устанавливают зависимости и запускают backend с frontend. Для production-режима используйте Docker Compose или отдельный сервисный менеджер; start-скрипты предназначены для локальной работы и испытаний.

## Первый вход

1. Откройте **http://localhost:3000**.
2. Включите **«Войти ключом администратора»**.
3. Откройте `.env` локально и скопируйте только значение после `API_KEY=`.
4. После входа перейдите в **«Настройки» → «Доступ сотрудников»**.
5. Создайте индивидуальные учётные записи. Для обычного входа сотрудники используют свои логины и пароли.

**Общего логина `admin` и пароля по умолчанию нет.** Не передавайте сотрудникам `API_KEY` и не публикуйте `.env`, скриншоты ключа или ссылки с секретами.

| Адрес | Назначение |
|---|---|
| http://localhost:3000 | Веб-интерфейс |
| http://localhost:3000/display | Полноэкранный режим видеостены для поста наблюдения |
| http://localhost:8000/docs | Swagger / документация API |
| http://localhost:8000/health | Проверка процесса API, не состояния всех камер |

На чистой установке камеры не создаются автоматически, а архив пуст. Это нормальное состояние, не ошибка запуска.

## Подключение камер

### Настоящая RTSP-камера

1. Назначьте камере статический IP и убедитесь, что сервер видит её в сети.
2. Добавьте разрешённые IP в `.env`:

   ```dotenv
   CAMERA_ALLOWED_HOSTS=["192.168.1.20","192.168.1.21"]
   ```

3. Перезапустите локальный backend. Для Docker выполните:

   ```bash
   docker compose up -d --force-recreate backend celery_worker
   ```

4. В разделе мониторинга нажмите добавление камеры и укажите её настоящий RTSP-адрес, например:

   ```text
   rtsp://USER:PASSWORD@192.168.1.20:554/stream
   ```

Путь потока зависит от производителя. Проверить адрес можно заранее в VLC. В рабочем режиме разрешены явно указанные IP; loopback, link-local и служебные имена блокируются. HTTP-источники по умолчанию отключены. Проверка URL в приложении не заменяет исходящий firewall и изоляцию сети камер.

### Знакомство без оборудования

Добавьте одну из демонстрационных камер вручную:

```text
sim://entrance
sim://hallway
sim://courtyard
```

Это синтетические сцены для проверки интерфейса и интеграции, **не доказательство качества на реальном видео**. Старые демонстрационные веса `school_security_best.pt` не активны по умолчанию.

## Модели YOLO и настройки

### Выбор базовой модели

Во вкладке **«Настройки» → «Версия YOLO»** администратор может выбрать:

| Семейство | Размеры | Назначение |
|---|---|---|
| YOLOv8 | N / S / M / L / X | Базовый COCO-детектор объектов |
| YOLO11 | N / S / M / L / X | Альтернативный базовый COCO-детектор |

**N** — наиболее лёгкий вариант семейства; более крупные модели требуют больше ресурсов. Выбор должен опираться на замеры FPS и качества на ваших сценах, а не только на размер модели.

Если весов нет, разрешите загрузку официальных файлов и нажмите **«Применить модель»**. Нужен доступ к GitHub. Перед переключением выполняются проверка и прогрев; при ошибке загрузки/проверки прежний детектор остаётся активным. Выбор общий для камер и сохраняется в БД.

> Стандартные COCO-веса YOLOv8/YOLO11 **не являются специализированным детектором оружия**. Оружейная модель и активные кастомные веса остаются отдельными. Новые задачи обучения используют выбранную базовую модель.

### Сотрудники и роли

| Роль | Права |
|---|---|
| Наблюдатель | Просмотр камер, архива, аналитики и своих настроек |
| Оператор | То же + анализ фото/видео и подтверждение инцидентов |
| Администратор | То же + управление камерами, удаление записей, модели, обучение и сотрудники |

Логин: 3–64 символа, строчные латинские буквы, цифры и допустимые разделители; пароль: от 12 символов. Права проверяются сервером. Отключение, смена роли или пароля отзывает сессии сотрудника; выход отзывает текущую сессию. Ротация `API_KEY` аннулирует все сессии.

### Персональный интерфейс

Каждый сотрудник может сохранить 1–4 колонки видеостены, показ статистики, журнала и баннера событий, компактный режим и стартовую вкладку. На узких экранах сетка адаптируется. Скрытие блока не меняет права доступа и не останавливает запись событий.

## Обучение на своих данных

Система обучает **кандидата**, а не автоматически заменяет рабочую модель.

1. Соберите реальные данные с разрешением на использование. Разделяйте train/val **по камерам или времени съёмки**, а не по соседним кадрам одного ролика. Для итоговой оценки оставьте независимый test-набор.
2. Разметьте **все** объекты целевых классов. Встроенный редактор рассчитан на один объект; для сложных сцен используйте внешнюю полную YOLO-разметку.
3. Загрузите данные через интерфейс или подготовьте структуру:

   ```text
   ml/datasets/custom/
   ├── images/
   │   ├── train/*.jpg
   │   └── val/*.jpg
   └── labels/
       ├── train/*.txt
       └── val/*.txt
   ```

4. Откройте **«Обучение»** и запустите задачу. Проверяются файлы, рамки, классы, точные дубликаты train/val и отсутствие синтетических `seed_*`. Минимум 6 train / 3 val — технический порог, **не достаточный объём для качества**.
5. Кандидат появится в `ml/models/candidates/job_ID.pt` со статусом `ready`. Камеры продолжают работать с прежней моделью. Каждый запуск — transfer learning от выбранной COCO-базы, не продолжение предыдущего обучения.
6. Проверьте кандидата отдельно на независимых данных. Только после этого нажмите **«Применить после проверки»**. Для возврата можно применить прежний кандидат, если его файл сохранён.

Формат строки разметки: `class_id center_x center_y width height`, координаты нормированы в 0–1. Классы: `0 dog`, `1 weapon`, `2 suspicious_bag`. Последний класс означает сумку-кандидат, а не её содержимое или намерения владельца.

Не используйте чужие непроверенные `.pt`: сериализованные модели требуют доверия к источнику. При аварийном завершении обучения статус может остаться `queued/running`; автоматическое восстановление таких задач пока не реализовано.

## Конфигурация и хранение данных

Основные параметры задаются в `.env`; образец — [`.env.example`](.env.example). После изменения серверных параметров перезапустите backend, а в Docker — также worker.

| Параметр | По умолчанию / смысл |
|---|---|
| `API_KEY` | Генерируется скриптом; аварийный административный доступ |
| `DATABASE_URL` | SQLite локально; PostgreSQL задаётся Compose |
| `CAMERA_ALLOWED_HOSTS` | Пустой список; укажите IP разрешённых камер |
| `MAX_CAMERAS` | 16 — лимит ресурсов, не гарантия производительности |
| `MAX_STORED_VIOLATIONS` | 250 записей архива |
| `UPLOAD_RETENTION_HOURS` | 24 часа для непривязанных результатов лаборатории |
| `MAX_UPLOAD_IMAGE_MB` / `MAX_UPLOAD_VIDEO_MB` | 15 / 60 МБ |
| `MAX_VIDEO_DURATION_SEC` | 120 секунд для лабораторного видео |
| `UNATTENDED_MIN_SECONDS` | 30 секунд наблюдения сумки |
| `ENABLE_LOCAL_TRAINING` | `true` локально; в Compose принудительно `false` |
| `COOKIE_SECURE` | `false` для localhost HTTP; включите при HTTPS |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | Пусто — Telegram-уведомления выключены |
| `NOTIFICATION_WEBHOOK_URL` | Пусто — webhook выключен |
| `NOTIFICATION_COOLDOWN_SEC` | 60 секунд на тип события |

Сохраняйте резервные копии **БД, `.env`, `media/`, своих датасетов и обученных весов**. БД содержит сотрудников, сессии, настройки и историю. Резервные копии с ключами и видеоматериалами должны быть защищены. Ротация архива и просроченных загрузок выполняется раз в минуту; политику хранения настройте до реальных испытаний.

Для локальной SQLite-установки можно создать копию данных:

```powershell
.\.venv\Scripts\python.exe scripts\backup_data.py
```

```bash
.venv/bin/python scripts/backup_data.py
```

Скрипт копирует БД, архив, пользовательский датасет и кандидатов в папку `backups/`, исключённую из Git. `.env` намеренно не копируется автоматически: сохраните его отдельно в защищённом хранилище. Для PostgreSQL в Docker используйте `pg_dump`, а не этот SQLite-скрипт.

## Частые вопросы

<details>
<summary><strong>Интерфейс не подключается к серверу</strong></summary>

Проверьте http://localhost:8000/health и вывод backend. Для локального запуска нужны два работающих терминала. В Docker посмотрите `docker compose ps` и `docker compose logs backend`. Порты 3000 и 8000 должны быть свободны; открывайте именно адрес, указанный в инструкции.

</details>

<details>
<summary><strong>Камера отклонена или не показывает видео</strong></summary>

Проверьте IP в `CAMERA_ALLOWED_HOSTS`, перезапуск backend после изменения `.env`, логин/пароль и RTSP-путь. Проверьте поток в VLC с машины сервера. Для Docker дополнительно проверьте доступность камеры из контейнерной сети. Не отключайте сетевые ограничения ради обхода ошибки.

</details>

<details>
<summary><strong>YOLO11 не скачивается или работает медленно</strong></summary>

Для загрузки нужен доступ к GitHub и достаточно свободного места. Начните с YOLO11 N; крупные модели требуют больше ресурсов. При ошибке загрузки/проверки рабочий детектор не заменяется. Статус установленного файла сам по себе не подтверждает качество модели.

</details>

<details>
<summary><strong>PowerShell блокирует npm или активацию venv</strong></summary>

Используйте `npm.cmd` и прямой путь `.\.venv\Scripts\python.exe`, как в Windows-инструкции. Ослаблять системную политику выполнения для этого не требуется.

</details>

<details>
<summary><strong>После обновления требуется войти заново</strong></summary>

Это ожидаемо при переходе со старого формата сессий, выходе, изменении роли/пароля, отключении сотрудника или ротации `API_KEY`. Для восстановления административного входа используйте ключ из своего `.env`.

</details>

## Безопасность и границы применения

- Не публикуйте Vite dev-сервер и API напрямую в интернет. По умолчанию порты привязаны к loopback.
- Для сетевого доступа настройте HTTPS reverse proxy, `COOKIE_SECURE=true`, конкретные `CORS_ORIGINS`, firewall и изолированную сеть камер. PostgreSQL/Redis не должны быть доступны извне.
- Не запускайте несколько uvicorn workers или backend-реплик: управление камерами и блокировки рассчитаны на один экземпляр API.
- Собака — обнаруженный объект, а не установленный факт безнадзорности. Содержимое сумок и намерения людей не распознаются.
- Правило сумки использует рамки и расстояния, а не идентификацию владельца. Перспектива и перекрытия влияют на результат.
- Возможны ложные срабатывания и пропуски, включая краткий показ оружия. Нужны независимые измерения precision/recall, ложных тревог на камеро-час и задержки до оператора.
- Клипы содержат предысторию без гарантированного постсобытийного фрагмента; при низком FPS длительность воспроизведения может отличаться от реального времени.
- Журнал действий доступен администраторам; это прикладной журнал в БД, а не защищённый от администратора неизменяемый аудит. MFA, самостоятельное восстановление пароля и автоматическое восстановление прерванного обучения пока не реализованы.
- До пилота проверьте длительную нагрузку, потери камер/сети, заполнение диска, резервное копирование и требования к персональным данным.

Подробности выполненных проверок и непроверенных условий: **[docs/REPAIR_NOTES.md](docs/REPAIR_NOTES.md)**.
